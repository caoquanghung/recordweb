This file serves as the persistent memory bank for AI agents working on **RecordWeb**. It tracks architectural decisions, technical constraints, environment configurations, current project phase, known quirks, and pending tasks.

## 1. Project Snapshot

* **Project**: RecordWeb — High-performance, client-side web recording studio.
* **Core Capabilities**: Screen, webcam, and audio recording with real-time video compositing (PiP, AI background removal/blur), Web Audio DSP filtering, 30 FPS regulation, and dual local/cloud export.
* **Technology Stack**:
  * **Framework**: Next.js 16.4.2 (App Router), React 19, TypeScript.
  * **Styling**: Vanilla CSS (CSS Modules & Custom Properties, adaptive light/dark Glassmorphism design tokens).
  * **Vision AI**: Google MediaPipe Selfie Segmentation (`@mediapipe/selfie_segmentation`) via WebGL/WASM.
  * **Audio Processing**: Native Web Audio API (`AudioContext`, `BiquadFilterNode`, `DynamicsCompressorNode`, `AnalyserNode`).
  * **Video Repair**: Client-side EBML binary duration patching (`fix-webm-duration`).
  * **Database**: Neon Serverless Postgres (`@neondatabase/serverless`) for metadata, presets, and catalogs.
  * **Authentication**: Clerk (`@clerk/nextjs`) with Next.js 16 `src/proxy.ts`.
  * **Video Object Storage**: Vercel Blob (`@vercel/blob/client`) for direct client-to-edge uploads.
  * **Lossless Segment Remuxing**: Mediabunny for client-side MP4/WebM parsing and encoded-packet merge without transcoding.
  * **Hosting**: Vercel (Next.js Edge CDN + Serverless Route Handlers in `src/app/api/*`).
  * **Cursor Capture Target**: The `extension/` Chromium Manifest V3 package automatically registers a Slides-scoped 24 Hz cursor tracker and publishes a random Capture Handle from every supported Google Slides document. Cursor correctness has priority over live preview: Standard Studio must fail closed when the exact picker-selected Slides tab and its live tracker cannot be verified, and recording must not start without an acknowledged cursor sampler. Standard Studio requires its microphone and mode-required camera first, then **Connect Google Slides** opens the native picker directly with no URL input or preselected target. The extension maps the returned track handle to the exact live tracker `tabId`; only a verified Slides stream is retained for preview. Pressing Start reuses that stream and keeps or returns focus to Studio for a visible three-second countdown; only when it completes does Studio focus the verified tab and begin the cursor/recorder handshake. Cursor trajectory schema v2 stores only samples with numeric normalized `x`/`y`; periods outside tracked content are omitted and appear as timestamp gaps. The URL validation/find-or-create/background `/present` module remains implemented but is intentionally disconnected from the UI. The in-tab End Session action waits for recording/cursor finalization before disconnecting all media. Static/build checks pass; unpacked-extension runtime verification is pending. The Electron helper is deprecated legacy fallback code.
  * **Extension App Origin**: `extension/manifest.json` is the production source of truth for the canonical HTTPS URL through `homepage_url`. `npm run extension:dev` generates an ignored, separate unpacked build under `artifacts/extension-development/` for `http://localhost:3000/`. The bridge and service worker accept only their own build's `homepage_url` origin; broad Vercel Preview access is absent. Use separate browser profiles or disable one variant because both inject into Google Slides.

## 2. Key Architectural Decisions & Invariants

1. **Framework Choice**: Next.js App Router + React 19 + TypeScript for end-to-end type safety, unified frontend and serverless route handlers, and zero-config Vercel deployment.
2. **Client-Side Video Compositor with React Hooks**:
   * Never place multiple independent video tracks in one `MediaRecorder`. The composite and each clean source use separate, single-video-track recorders coordinated by one session hook.
   * Composite Screen (background) + Webcam (PiP overlay) onto a single `1920x1080` `<canvas>` surface.
   * Frame loop is locked to 30.0 FPS via delta-time throttling (`~33.33ms`) in `requestAnimationFrame`.
   * Capture stream generated via `canvas.captureStream(30)`.
   * Encapsulated in `src/hooks/useCanvasCompositor.ts`.
3. **Web Audio Graph Topology**:
   * Order: Mic Source $\rightarrow$ High-Pass (80Hz) $\rightarrow$ Peaking (2.8kHz, +4dB) $\rightarrow$ Low-Pass (12kHz) $\rightarrow$ Dynamics Compressor (-24dB, 4:1) $\rightarrow$ Noise Gate $\rightarrow$ Master Audio Destination.
   * System audio (from `getDisplayMedia`) is mixed into master destination without passing through vocal mic filters.
   * `AnalyserNode` connected for real-time VU meter (`VuMeter.tsx`).
   * Encapsulated in `src/hooks/useAudioDSP.ts`.
4. **Environment-Aware Direct Client Upload to Vercel Blob**:
   * Standard Vercel Serverless Functions have a 4.5MB request body size limit.
   * Video recordings are far larger than the 4.5MB serverless body limit, especially at the 30-minute maximum.
   * Videos **MUST** be uploaded directly from the browser to edge storage through `src/app/api/upload/route.ts`. Every environment prefers `upload()` / `handleUpload()` whenever `BLOB_READ_WRITE_TOKEN` is configured; Vercel OIDC, `BLOB_STORE_ID`, and `BLOB_WEBHOOK_PUBLIC_KEY` provide the `uploadPresigned()` / `handleUploadPresigned()` fallback when the read-write token is absent. At Vercel Function runtime, the OIDC token comes from the `x-vercel-oidc-token` request header rather than `process.env`.
   * Resulting CDN URL is stored in Neon Postgres `recordings.storage_url`.
5. **Resilient Dual Storage**:
   * Local: Immediate direct download as `.webm` (with EBML duration fix in `src/lib/ebmlPatcher.ts`) + automatic IndexedDB session backup (`src/lib/idb.ts`).
   * Cloud: automatic post-finalization direct upload to Vercel Blob with metadata in Neon Postgres via `src/app/api/recordings/route.ts`; a required title is saved afterward.
6. **UI Standard**: Strictly Vanilla CSS (CSS Modules & custom properties) with adaptive light/dark studio glassmorphism (tokens in `docs/ui_ux_specification.md`). Theme defaults to the OS preference and persists in `localStorage` as `recordweb-theme`; Studio, Settings, and `AppSidebar` controls share `useAppTheme`, which synchronizes same-document controls and other browser tabs while `html[data-theme]` drives every authenticated screen. No Tailwind or heavy CSS frameworks.
7. **Documentation Source of Truth**: `docs/system_architecture.md` is a stale legacy snapshot and is not authoritative. Current subsystem boundaries and behavior must be verified from code, types, tests, route contracts, and maintained domain documents. `docs/audio_video_pipeline.md` remains authoritative for the media pipeline; `docs/ui_rebuild_impact_analysis.md` is the maintained UI boundary/risk inventory. `MEMORY.md` is the persistent state bank.
8. **Multi-Asset Output**: A session produces the composite plus available clean 720p webcam, normalized 1080p tab video, standalone mixed audio, processed microphone audio, gained tab audio, and a 24 Hz cursor JSON. Chrome's mandatory native picker supplies tab video/audio, and the extension resolves that exact picker-selected Google Slides tab as the single cursor/focus target. Existing Electron cursor code is legacy until the extension replacement is runtime-verified.
9. **Cross-Session Lecture Projects**: A lecture is an owned `recording_projects` row with ordered associations to independently finalized `recordings`. Each later recording session creates a new immutable segment; no `MediaRecorder` is resumed after reload. Logical playback derives one global timeline, while optional physical merge copies compatible encoded packets without decode/encode. Source recordings remain intact.
10. **In-App Presentation Recording**: PDF/PPTX presentation mode uses a separate self-tab capture path rather than `CanvasCompositor`. The presentation DOM will contain the rendered slide, raw webcam overlay, and baked custom cursor; `getDisplayMedia()` provides one current-tab video track, while captured tab audio and microphone audio flow through the existing Web Audio graph. Presentation files remain local in the initial implementation, and MediaPipe blur/cutout is not used in this mode.
11. **Client-Side Recording Archives**: Composite and all available separate-source downloads are assembled into one browser-generated ZIP with `client-zip` and never proxied through a Route Handler. Each entry uses `<recording-name>-<component>.<extension>` and the archive uses `<recording-name>-assets.zip`.
12. **Authenticated Entry Routing**: `/` is a thin server redirect to `/dashboard`, making Dashboard the first screen users encounter. The recording Studio is canonical at `/studio`; all Studio navigation, quick-start, preset, recovery, and new-recording actions must target `/studio`.
13. **Application RBAC**: The two-role `user`/`developer` authorization layer is implemented in code. Clerk `publicMetadata.appRole` is the source of truth; signed session claims drive runtime authorization and applied migration `0006_user_roles` adds the webhook-maintained Neon mirror. `/api/health` requires `diagnostics:internal`, `/component/sidebar` requires `experiments:use`, and invalid/missing roles fail closed to `user`. `developer` never implies cross-user recording access. Presentation Studio is a core feature for both roles. Clerk claim-template setup and authenticated two-role E2E remain manual.
14. **Role-Aware Recording Previews**: Standard recording previews in Studio/Presentation Review, Library, and Recording Details render the composite video with mixed audio for both roles. `user` sees only that composite. `developer` additionally receives the permission-gated `RecordingDeveloperInspection` panel with source-asset inventory, mixed/microphone/system-audio waveforms, and cursor trajectory when available. This permission never bypasses recording ownership/share/public access. Auxiliary assets remain recorded, persisted, uploaded, and available to the archive pipeline.
15. **Unified Blue UI Theme**: Dashboard and the light `AppSidebar` palette are the brand-color source of truth (`#1d4ed8`, `#2563eb`, `#1e40af` plus blue soft/border/focus variants). Shared semantic tokens in `src/app/globals.css` now drive active Studio/Presentation, Settings, Share, global media controls, Privacy, and Library/Details/Sidebar dark overrides per `docs/note-note/color-theme-standardization.md`. Semantic record/danger red, success green/teal, warning amber, and neutral colors retain their meanings; inactive legacy UI remains deferred until reuse or removal. In Standard Studio setup, Connect Audio + Webcam stays dark blue before connection and light blue afterward; the available Google Slides action is amber. The next available action pulses in brightness and size as a whole button, with animation disabled for reduced-motion users.
16. **Fixed Standard Studio Workspace**: Standard Studio setup/recording fills one browser viewport without page-level vertical scrolling. The source inspector owns overflow for its advanced controls. One minimal microphone activity bar lives in its first connection card; Presentation retains its microphone/system meter and the recording/audio pipeline remains unchanged.
17. **Automatic Review Persistence**: Entering Studio or Presentation Review starts direct upload of the finalized composite and available source assets before title entry. Neon receives a deterministic temporary title because the schema requires one. The required user title then updates only the owned recording row before local title finalization, sharing, ZIP download, or a full-page return to `/studio`. Metadata POST checks the owner/local ID before insertion so retry after a lost response does not duplicate a recording. The developer permission gate remains the only review waveform/cursor UI.
18. **Extension Build Separation**: Keep `extension/manifest.json` publication-only. Generate a distinct localhost unpacked build with `scripts/build-extension-dev.mjs`; do not broaden Store host permissions for local tests. `scripts/package-extension.mjs` refuses to overwrite an existing versioned ZIP and validates the package before copying it to `artifacts/chrome-web-store/`. Version `0.4.8` is backed up under `extension/releases/`; commit that archive and the matching source revision for durable backup.
19. **Shared Mic/Camera Toggle State**: `MediaSessionProvider` owns microphone mute and camera visibility across Studio, Presentation, route navigation, and the global devices panel. Mic mute keeps the Web Audio DSP gain ramp and disables the raw audio track after it reaches silence; camera off disables the shared video track and hides its preview/composite overlay. The shared Studio toggle UI shows state-specific icons and disables controls when a source is disconnected. Global disconnect still stops owned tracks.

## 3. Environment & Configuration State

* **Node.js**: `v26.7.0` | **npm**: `11.19.0`
* **Local Secrets File**: `.env.local` (ignored by Git)
  * `DATABASE_URL`: Neon pooled Postgres connection string (`postgresql://...pooler...neon.tech/neondb?sslmode=require`).
  * Blob storage prefers `BLOB_READ_WRITE_TOKEN` in Production, Preview, and local Development. `BLOB_STORE_ID`, `VERCEL_OIDC_TOKEN`, and `BLOB_WEBHOOK_PUBLIC_KEY` are optional fallback credentials when the read-write token is unavailable.
* **Database Schema**:
  * `users` table (id, email, display_name, role, created_at); `role` is live through applied migration `0006_user_roles`.
  * `recordings` table (id, **user_id FK**, title, **recorded_at session timestamp**, duration_seconds, file_size_bytes, resolution, fps, mime_type, local_id, storage_url, blob_pathname, **is_public**, settings, created_at). `recorded_at` is live through applied migration `0007_recording_recorded_at`; existing rows were backfilled from `created_at`.
  * `recording_assets` table (id, **recording_id FK**, kind including mixed/microphone/system audio and cursor JSON, storage_url, blob_pathname, mime_type, file_size_bytes, resolution, fps, sample_rate_hz, metadata, created_at).
  * `recording_projects` table is live through applied migration `0005_recording_projects` (owner, title, draft/completed status, locked media profile, settings, optimistic revision, timestamps).
  * `recording_project_segments` table is live through applied migration `0005_recording_projects` (project-to-finalized-recording association, ordered sequence, inspected media profile).
  * `studio_presets` table (id, **user_id FK**, preset_name, pip_shape, pip_size, pip_position, bg_removal_mode, filters_config, updated_at).
  * `recording_shares` table (recording_id, recipient_user_id, permission, created_at).
  * `schema_migrations` table tracks ordered `psql` migrations.

## 5. Known Gotchas & Browser Quirks

| Quirk / Constraint | Impact | Solution |
| :--- | :--- | :--- |
| **MediaStream Track Hardware Lock** | Camera/Mic light stays on after stop | Always iterate `stream.getTracks()` and call `track.stop()`. |
| **AudioContext Autoplay Policy** | Audio is muted or suspended initially | Check `audioContext.state === 'suspended'` and call `resume()` on user click. |
| **WebM Missing Duration in Chrome** | Video timeline cannot be scrubbed | Run `fix-webm-duration` EBML patcher on recorded blob before export. |
| **Vercel Serverless 4.5MB Payload Limit** | Video upload crashes with HTTP 413 | Use `@vercel/blob/client` direct browser upload; never send video chunks to serverless handler body. |
| **Inference CPU Spike** | Canvas framerate drops below 30 FPS | Run MediaPipe segmentation on downscaled resolution (256x256) and upscale the mask. |
| **Next.js SSR vs Browser Media APIs** | `navigator.mediaDevices` undefined on server | Guard all media access with `"use client"` and React `useEffect` / event handlers. |
| **Noise Gate Step Change** | Audible clicking/popping artifacts | Use `gainNode.gain.setTargetAtTime()` with 10ms attack / 100ms release — never `gain.value = 0`. |
| **Safari WebM Playback** | Shared videos fail to play in Safari/iOS | Detect MP4/AVC support at session start; prefer `video/mp4` if available; show compatibility notice on `/share/` page. |
| **A/V Desync over Long Sessions** | Audio and video drift out of sync after ~15 min | Use delta-clamped RAF timer; enforce 30-min hard stop; UI warns at 15 min. |
| **Neon Schema Drift** | Application code can fail when a schema change is deployed without its migration | Add a new ordered SQL file, run `npm run db:status`, `npm run db:migrate`, and `npm run db:verify`; never edit an applied migration. Initial schema was applied on 2026-10-10. |
| **Conditional Canvas Mount** | Calling `captureStream()` before the source-driven preview canvas mounts produces no output stream | Reinitialize canvas capture when visual-source availability changes; the compositor owns and stops only its generated track. |
| **Extraneous MediaPipe Package** | Local builds may resolve `@mediapipe/selfie_segmentation` from `node_modules` while clean Vercel builds fail with TS2307 | Keep the exact MediaPipe package version declared in both `package.json` and `package-lock.json`; verify with `npm ls` and `npm run build`. |
| **Public Blob URL vs Page Authorization** | The share page enforces owner/public/direct-recipient access, but anyone who obtains the underlying URL can fetch an object from a public Blob store | Treat public-link publishing as intentional exposure; migrate to a private Blob store plus an authorized delivery endpoint before handling sensitive recordings. |
| **Clerk Dev Proxy Origin** | Playwright requests through `127.0.0.1` can trigger Clerk development-proxy socket resets | Use `http://localhost:3000` consistently for the Playwright base URL and local web server. |
| **Blob Store Access Mismatch** | If the client `access` option differs from the connected Blob store mode, uploads can remain at 0% and no metadata request is sent | Keep the current MVP store and client set to `public`. Private storage would also require an authenticated delivery route or short-lived signed URLs. |
| **Blob MIME Allowlist Mismatch** | `MediaRecorder` reports codec-qualified MIME values such as `video/mp4;codecs=avc1,mp4a.40.2`, while the upload token permits base types | Normalize only the Blob upload `contentType` to `video/mp4` or `video/webm`; retain the codec-qualified MIME value in recording metadata. |
| **Blob Credential Priority** | `handleUpload()` only understands a read-write token, while OIDC-only stores require the presigned upload path; additionally, Vercel Functions deliver the runtime OIDC token through `x-vercel-oidc-token`, so reading only `process.env.VERCEL_OIDC_TOKEN` fails on deployed functions | Prefer `BLOB_READ_WRITE_TOKEN` in every environment. Only fall back to presigned uploads with `BLOB_STORE_ID` and `BLOB_WEBHOOK_PUBLIC_KEY` when it is absent, and resolve OIDC from the request header with an environment fallback for build/local; never expose credentials to the browser. |
| **Concurrent Encoder Load** | Composite, webcam, and screen encoding can saturate low-power devices and cause dropped frames | Keep one video track per recorder, use fixed-rate normalization canvases, expose partial results, and validate real 30-minute sessions on target hardware. |
| **Background-Tab RAF Suspension** | Switching to another browser tab pauses `requestAnimationFrame`, freezing canvas-derived composite, screen, and webcam frames while audio continues | Use `src/lib/frameScheduler.ts`: RAF in visible tabs and a worker timer while `document.hidden`; retain delta clamping and test target browsers. Full browser/OS process suspension remains outside webpage control. |
| **Native Picker/Extension Identity Gap** | `getDisplayMedia()` does not expose the selected Chrome tab ID, so preselecting a tracker target can diverge from the tab the user actually shares | Extension `0.3.9` publishes a random opaque Capture Handle in each supported Slides document, registers it with the service worker, and resolves the captured track handle back to the exact live tracker `tabId`. Stop unverifiable/mismatched streams; do not infer identity from track labels or titles. |
| **Post-Picker Capture Handle Race** | `getDisplayMedia()` can resolve before the captured track exposes its handle or before the Slides tracker registers that handle with the service worker, causing a valid stream to flash its sharing indicator and then be stopped | Version `0.4.1` waits up to 2.5 seconds on both boundaries, listens for `capturehandlechange`, and rejects only after the tracker mapping still cannot be established. Tabs opened before an extension reload still require a page reload. |
| **MV3 Worker Suspension Orphans Extension Ports** | Runtime evidence showed `getCaptureHandle()` succeeding immediately while the valid display stream was still rejected and stopped. Chrome MV3 may suspend an idle service worker; opening a long-lived port alone does not reset its idle timer, and the old app/tracker scripts treated `onDisconnect` as permanent. The restarted worker lost its in-memory ports, handle mappings, and target state while existing tabs stayed stale until reload | Extension `0.4.5` reconnects both content-script ports with bounded backoff, queues app messages, re-registers tracker handle/session state, re-adopts a verified target from subsequent focus/cursor traffic, and grants tracker replacement a short grace window before reporting target loss. Keepalive is not used as the correctness mechanism. |
| **Slides Replaces Early Capture Handle Config** | Runtime inspection showed `setCaptureHandleConfig()` succeeds when reapplied after Slides initialization while the `document_start` configuration can later yield a live browser track with a null handle | Version `0.4.3` reuses one opaque handle and reapplies it at bounded DOM/load/pageshow checkpoints through five seconds; publish the DOM handle only after Chrome accepts the configuration. |
| **Repeat Slides Capture Can Require Reload** | A previously recorded Slides tab could fail the next Connect until reloaded because the producer reapplied Capture Handle only during initial load; Slides could later clear the browser configuration while the DOM attribute and service-worker mapping remained stale | Extension `0.4.5` broadcasts an on-demand preparation message before every picker, makes the MAIN-world producer synchronously reapply the same handle, and makes the tracker immediately re-register it. Studio deliberately does not await this work before `getDisplayMedia()`, preserving transient user activation. Reload remains necessary only after an extension update or invalidated content-script context. |
| **Reloading the Target Slides Tab Loses an Active Cursor Session** | A document reload recreates the MAIN-world Capture Handle and the isolated tracker/sampler state. Before recording, the same Chrome `tabId` can usually be re-adopted if the tracker reconnects within the 2.5-second grace period. During recording, however, the new sampler has no `sessionId`, timestamp, pause state, or sample index; the service worker does not persist or replay `CURSOR_START` with `offsetMs`/`startIndex`. A fast reconnect can therefore leave video recording active while cursor sampling has stopped, and final `CURSOR_STOP` will time out without `CURSOR_STOPPED`/`cursor.json`; a slower reconnect emits `TARGET_ENDED` and stops recording. | Treat target-tab reload during an active recording as unsupported until session recovery is implemented. Persist the active cursor-session checkpoint outside the content script and rehydrate the replacement tracker, or fail closed immediately on any tracker document reload. The `extension/README.md` claim that active cursor sessions resume after same-tab reload is not reflected in the current implementation and must not be relied on. |
| **Canonical Extension Site Is Not Currently Reviewer-Testable** | Live checks on October 26, 2026 returned HTTP 404 for `https://recordweb-nine.vercel.app/`, `/dashboard`, and `/studio`; `/privacy` returned 200. The extension action and reviewer instructions depend on the canonical homepage, so Store review cannot complete the advertised flow against the current deployment. | Deploy the functional application at the `homepage_url`, verify the reviewer routes without relying on a Preview hostname, and provide working review credentials/instructions when authentication is required. |
| **Picker May Focus the Captured Tab** | Chromium may activate the selected surface when `getDisplayMedia()` completes, interrupting Studio setup before the user presses Start | Create a new `CaptureController` for every display request and prefer `focus-capturing-application`, falling back to `no-focus-change`; retain extension `FOCUS_APP` after target verification for compatibility. Only Start may focus the selected Slides tab. |
| **Display Permission Is Per Session** | `getDisplayMedia()` permission cannot be persisted, even though cursor host access is granted at extension installation | Invoke the native picker from Connect for every new display stream, retain that provider-owned stream for setup preview and Start, and let extension installation remove only the separate toolbar/shortcut authorization step. |
| **Extension Callback Can Outlive User Activation** | Waiting for `TARGET_READY` before calling `getDisplayMedia()` can let Chromium expire the Connect click's transient activation | The default Studio flow no longer waits for extension preparation: Connect invokes the picker immediately, then resolves the selected tab through Capture Handle. Keep URL-based preparation detached from this UI path. |
| **Blank Webcam During Segmentation Startup** | MediaPipe publishes its output canvas before the first result, so drawing that blank canvas hides an otherwise-ready webcam | Pass the effect canvas to the compositor only while segmentation state is `running`; use the raw webcam during loading or error states. |
| **Optional-Chaining Null Comparison** | `captureSession?.timer !== null` evaluates true when `captureSession` is null because the expression yields `undefined`, then a direct `.timer` read crashes the first cursor start | Use the nullish check `captureSession?.timer != null`; the Electron smoke test calls reset twice before initialization to protect idempotent cleanup. |
| **Display Stream Outlives Recorder Stop** | Stopping MediaRecorders before finalization is complete cannot immediately stop their provider-owned raw input tracks | After recording reaches `ready` or `error`, stop the native display stream without disconnecting the selected cursor target; manual global Disconnect still releases all devices and the extension target. |
| **Persistent Slides Tracker Context** | Static content scripts retain their pointer/keyboard listeners while a selected Slides tab remains open | `CURSOR_STOP`, `CURSOR_RESET`, and manual disconnect stop sampling immediately; the small event-listener context remains ready for another session and is torn down on navigation, tab close, or extension reload. |
| **Slides Fullscreen Frame Hides Pointer Events** | Runtime testing showed the 24 Hz sampler and End Session control remained alive in Google Slides fullscreen, but cursor movement over the presented slide was not observed; moving onto the extension-owned control updated the cursor again. The presentation surface handles pointer events in a child frame/layer whose events do not bubble to the top-document listener | Extension `0.4.4` adds a minimal all-frame pointer sensor for matching Slides and eligible `about:blank` frames, maps coordinates through nested frame bounds, and relays them to the single top-frame tracker without duplicating controls or tracker ownership. | **Slides Navigation Dropped Cursor Asset** | A same-tab Slides presentation/fullscreen navigation disconnects the old content-script port. | **Reused Edit Tab Spawned Untracked Presenter** | Version `0.3.2` focused a matching `/edit` tab without changing its URL. Long multi-asset recordings can therefore retain substantially more renderer memory than the exported file size until reset or tab close | After successful persistence and pending draft completion, clear chunk/spec/recorder refs while retaining only the review assets that the UI still needs. Profile heap and native/GPU memory separately because Blob backing storage is not fully represented by JS heap. |
| **IndexedDB Checkpoint Write Amplification** | Every non-empty one-second chunk from every active recorder invokes `checkpointDraft()`, and each queued checkpoint rewrites a snapshot containing the complete accumulated chunk arrays for every asset. With up to six recorders this can cause several ever-growing full IndexedDB writes per second and near-quadratic total I/O over a long session | Coalesce/debounce checkpoints to one bounded-frequency writer, avoid enqueuing redundant snapshots, and persist only newly produced chunks or use a normalized per-session/per-asset chunk store. Measure write throughput and queue depth during long recordings. |
| **Studio Eagerly Loads Full Recovery Drafts** | Studio mount calls `getRecordingDrafts()`, which deserializes every draft including every stored media `Blob[]`, then keeps the complete drafts in React state even before a recording session starts. Old or interrupted multi-asset sessions can therefore cause high baseline renderer memory | Add a lightweight draft-index query that returns metadata only; load one draft's chunks lazily when the user explicitly starts recovery. Provide stale-draft size visibility and deletion controls. |
| **Preview Pipeline Runs Before Recording** | Connecting sources immediately activates the 30 FPS composite canvas, Web Audio graph/meter RAF, and—by default because the Studio starts in `screen-pip` + `blur`—MediaPipe inference. These costs are tied to source availability rather than recording status, so setup mode can already consume significant CPU/GPU memory | Introduce explicit preview activity/quality control: low-rate or lower-resolution idle preview, suspend inference/audio metering when panels are hidden or sources are inactive, and raise to recording quality only during countdown/recording. |
| **Adaptive Sidebar Followed Page Scroll** | Desktop `AppSidebar` instances used `position: sticky`, so their viewport anchoring still depended on the page scroll container and shell height | Keep adaptive mode fixed to the viewport on desktop and reserve the 288px content column explicitly; retain the fixed off-canvas drawer behavior below 840px. |
| **Merged Output Memory Cost** | `segmentMerger.ts` currently writes the complete remuxed MP4/WebM to a Mediabunny `BufferTarget`, so a long lecture requires memory for the output plus bounded input caches | Keep merge optional, retain immutable source segments, show resource guidance in the future UI, and add File System Access or append-only streaming output before targeting very large lectures. |
| **Same MIME Is Not Merge Compatibility** | Independently finalized files can share a MIME string while differing in codec configuration, resolution, audio layout, or key-frame boundaries | Inspect every Blob with Mediabunny and compare the stored immutable media profile; reject mismatches and never silently transcode. |
| **Self-Tab Capture Is Permission-Gated** | `preferCurrentTab` only promotes “This Tab”; it cannot silently select it, and unsupported browsers may not expose Capture Handle or Element Capture | Start capture from a user gesture, reject reported non-tab surfaces, verify the capture handle when available, and use clean full-tab presenter mode only as the explicit fallback. |
| **Source Release Can Invalidate Review Preview** | Releasing presentation capture after finalization changes the live cursor-controller prop. If recorder cleanup depends on that prop, React runs the cleanup and revokes the freshly created preview Object URL, leaving Review black at `0:00` even though the IndexedDB Blob is valid | Pin the cursor controller per recording session in `useRecordingSession`; keep unmount cleanup independent of live controller identity, and revoke preview URLs only on replacement, explicit reset, or actual unmount. |
| **Presentation Deck Outlives Recording Reset** | Recording state and the locally rendered PDF/PPTX deck have separate owners, so resetting Review alone can carry the previous lecture file into the next session | On “Record another” in the Presentation workspace, call `presentationDeck.clear()` so the renderer is disposed, pending renders are invalidated, and the upload state returns to idle. |
| **PPTX Browser Font Substitution** | `pptx-browser` may request mapped Google Fonts and cannot guarantee PowerPoint-perfect charts, SmartArt, embedded media, or typography | Keep the file itself local, pin the renderer version, surface fidelity limitations in the future UI, and runtime-test representative decks before expanding the supported feature claim. |
| **PPTX Player Is Experimental** | `pptx-browser@4.1.5` exposes click-group and transition playback, but its object-animation compositor does not yet render each shape independently, so parsed entrance/exit/emphasis effects may remain visually static | Treat the integration as a runtime experiment, advertise only verified transitions, and test representative animated decks before deciding whether to fork the renderer or move processing to a dedicated presentation engine. |
| **Clerk Route Matcher Deprecation** | Clerk 7.9.14 warns that `createRouteMatcher` will be removed because path-based middleware checks can diverge from resource access | Keep permission checks inside every privileged page/Route Handler. Migrate the remaining coarse authenticated-route protection from `createRouteMatcher` to Clerk's resource-based pattern before the next Clerk major upgrade. |
